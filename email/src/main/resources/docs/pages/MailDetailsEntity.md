# Mail Details Entity

## Overview

The **Mail Details** entity represents an email message with all its properties including sender, recipients, subject, message body, attachments, and metadata. This entity is used as input/output for various catalog requests in the Email Extension.

## Entity Structure

**Entity Name**: Mail Details  
**Primary Key**: Message ID

## Fields

| Field Name | Type | Required | Description |
|------------|------|----------|-------------|
| **From** | Text | No | Sender's email address |
| **To** | Text | Yes | Primary recipient email addresses (comma-separated) |
| **Subject** | Text | Yes | Email subject line |
| **Message** | RichText | Yes | Email body content (supports HTML) |
| **File Attachment** | File (Multiple) | No | File attachments (PDF, DOCX, images, etc.) |
| **Item attachment** | [ Label ] | No | Item attachments (calendar items, contacts, etc.) |
| **Reference attachment** | File | No | Reference attachment |
| **Message ID** | Text | No | Unique message identifier |
| **Cc** | Text | No | Carbon copy recipients (comma-separated) |
| **Bcc** | Text | No | Blind carbon copy recipients (comma-separated) |
| **Is Read** | Boolean | No | Whether the email has been read |
| **Reply To** | Text | No | Reply-to email address |
| **Send Date and Time** | Date (with time) | No | When the email was sent |
| **Received Date and Time** | Date (with time) | No | When the email was received |
| **Categories** | [ Text ] | No | Email categories/labels |

## Field Details

### From
- **Type**: Text
- **Format**: Email address
- **Example**: `"john.doe@example.com"`
- **Description**: Email address of the sender
- **Read-Only**: Yes (set by email server)
- **Use Case**: Identify who sent the email

### To
- **Type**: Text
- **Required**: Yes (for sending emails)
- **Format**: Comma or semicolon-separated email addresses
- **Example**: `"user1@example.com, user2@example.com"`
- **Description**: Primary recipients of the email
- **Multiple Recipients**: Supported (separated by comma or semicolon)

### Subject
- **Type**: Text
- **Required**: Yes (for sending emails)
- **Format**: Plain text
- **Example**: `"Monthly Report - January 2024"`
- **Description**: Email subject line
- **Max Length**: No hard limit, but email clients may truncate long subjects

### Message
- **Type**: RichText
- **Required**: Yes (for sending emails)
- **Format**: HTML or plain text
- **Example**: `"<p>Please find the report attached.</p>"`
- **Description**: Email body content
- **HTML Support**: Yes (full HTML formatting supported)

### File Attachment
- **Type**: File (Multiple)
- **Required**: No
- **Format**: Any file type
- **Example**: PDF, DOCX, XLSX, images, etc.
- **Size Limit**: 
  - Gmail: 25 MB total
  - Outlook: 35 MB total (20 MB per file)
- **Description**: Files attached to the email
- **Multiple Files**: Supported

### Item attachment
- **Type**: [ Label ]
- **Required**: No
- **Format**: Array of labels
- **Example**: `["Calendar Event", "Contact Card"]`
- **Description**: Non-file attachments (calendar items, contacts, etc.)
- **Use Case**: Outlook-specific item attachments

### Reference attachment
- **Type**: File
- **Required**: No
- **Format**: Single file
- **Description**: Reference attachment (Outlook-specific)

### Message ID
- **Type**: Text
- **Required**: No (auto-generated by email server)
- **Format**: Unique identifier (typically enclosed in angle brackets)
- **Example**: `"<CABc123xyz@mail.gmail.com>"`
- **Description**: Globally unique identifier for the email
- **Primary Key**: Yes
- **Use Case**: Used for [Move Message](pages/MoveMessage.md) operations

### Cc
- **Type**: Text
- **Required**: No
- **Format**: Comma or semicolon-separated email addresses
- **Example**: `"manager@example.com, team@example.com"`
- **Description**: Carbon copy recipients (visible to all recipients)

### Bcc
- **Type**: Text
- **Required**: No
- **Format**: Comma or semicolon-separated email addresses
- **Example**: `"archive@example.com"`
- **Description**: Blind carbon copy recipients (hidden from other recipients)

### Is Read
- **Type**: Boolean
- **Required**: No
- **Values**: `true` (read), `false` (unread)
- **Example**: `false`
- **Description**: Whether the email has been read
- **Use Case**: Filter unread emails in [Retrieve Unread Emails](pages/RetrieveUnreadEmailsFromFolder.md)

### Reply To
- **Type**: Text
- **Required**: No
- **Format**: Email address
- **Example**: `"noreply@example.com"`
- **Description**: Email address where replies should be sent
- **Default**: If not specified, replies go to the sender's email address

### Send Date and Time
- **Type**: Date (with time of day)
- **Required**: No
- **Format**: Unix timestamp (milliseconds)
- **Example**: `1704326400000` (January 4, 2024, 00:00:00 UTC)
- **Description**: When the email was sent
- **Read-Only**: Yes (set by email server)

### Received Date and Time
- **Type**: Date (with time of day)
- **Required**: No
- **Format**: Unix timestamp (milliseconds)
- **Example**: `1704330000000` (January 4, 2024, 01:00:00 UTC)
- **Description**: When the email was received by the server
- **Read-Only**: Yes (set by email server)

### Categories
- **Type**: [ Text ]
- **Required**: No
- **Format**: Array of category names
- **Example**: `["Important", "Work", "Follow-up"]`
- **Description**: Email categories or labels
- **Use Case**: Outlook categories, Gmail labels

## Usage in Catalog Requests

### Input Entity (Send Mail)

When sending an email, provide the following required fields:

```json
{
  "To": "recipient@example.com",
  "Subject": "Test Email",
  "Message": "<p>This is a test email.</p>",
  "Cc": "manager@example.com",
  "Bcc": "archive@example.com",
  "Reply To": "noreply@example.com",
  "File Attachment": [file1, file2]
}
```

### Output Entity (Fetch Mails, Retrieve Unread Emails)

When retrieving emails, the entity includes all fields:

```json
{
  "From": "sender@example.com",
  "To": "recipient@example.com",
  "Subject": "Received Email",
  "Message": "<p>Email content here.</p>",
  "Message ID": "<abc123@mail.gmail.com>",
  "Cc": "manager@example.com",
  "Is Read": false,
  "Send Date and Time": 1704326400000,
  "Received Date and Time": 1704330000000,
  "File Attachment": [...]
}
```

## Field Mapping

### Gmail Mapping

| Mail Details Field | Gmail API Field |
|-------------------|-----------------|
| From | `from` header |
| To | `to` header |
| Subject | `subject` header |
| Message | `body` (HTML or plain text) |
| Message ID | `message-id` header |
| Cc | `cc` header |
| Bcc | `bcc` header |
| Is Read | `UNREAD` label (inverted) |
| Send Date and Time | `date` header |
| Received Date and Time | `internalDate` |
| Categories | Gmail labels |

### Outlook Mapping

| Mail Details Field | Outlook API Field |
|-------------------|-------------------|
| From | `from.emailAddress.address` |
| To | `toRecipients[].emailAddress.address` |
| Subject | `subject` |
| Message | `body.content` |
| Message ID | `internetMessageId` |
| Cc | `ccRecipients[].emailAddress.address` |
| Bcc | `bccRecipients[].emailAddress.address` |
| Is Read | `isRead` |
| Send Date and Time | `sentDateTime` |
| Received Date and Time | `receivedDateTime` |
| Categories | `categories` |

## Validation Rules

### Required Fields (for sending)
- **To**: Must contain at least one valid email address
- **Subject**: Cannot be null or empty
- **Message**: Cannot be null or empty

### Optional Fields
- All other fields are optional
- If not provided, they will be null or empty

### Email Address Format
- Must contain `@` symbol
- Must have domain part (e.g., `example.com`)
- Example: `user@example.com`

### Attachment Size Limits
- **Gmail**: 25 MB total for all attachments
- **Outlook**: 35 MB total, 20 MB per individual file

## Best Practices

### 1. Always Provide Required Fields
When sending emails, always provide To, Subject, and Message fields.

### 2. Use Message ID for Operations
Use the Message ID field when moving or referencing specific emails.

### 3. Check Is Read Status
Use the Is Read field to filter unread emails.

### 4. Handle Attachments Properly
Check attachment sizes before sending to avoid exceeding provider limits.

### 5. Parse Dates Correctly
Send Date and Time and Received Date and Time are Unix timestamps in milliseconds.
